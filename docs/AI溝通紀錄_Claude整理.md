## 對話經過

### 1. 貼上測驗題目

**使用者：** 貼上「智慧訂單與促銷引擎」測驗題目（模型、折扣引擎、非同步通知三個模組）。

**Claude：**
- 提醒題目標註要通知面試官切換 View 權限。
- 指出 Email 需求互相矛盾：兩處說用 Mock，一處要求實際寄送。決定兩個都做，預設 Mock，可切換 SMTP。
- 把 `java.version` 從 17 改成 21，以使用正式版 virtual threads。
- 完成三個模組與測試，`mvn test` 30 個全過，含 `smtp` 模式從付款到收信的端到端測試。
- 列出自行決定的折扣規則，請使用者向面試官確認。
- 推測模組三的題目可能沒貼完整（後來確認是多慮，見第 6 點）。

### 2. 講解作業內容

**使用者：** 「AI作業要求的有哪幾點整理出來 然後跟我講解這些是捨麼你做了哪些事情」

**Claude：** 整理技術限制與三個模組的要求，逐項說明意思與做法，並列出題目沒明講而自行加上的部分，以及每個測試檔測什麼。

### 3. 如何人工測試

**使用者：** 「那我人工可以怎麼測試」

**Claude：**
- 專案沒有可直接操作的入口，新增測試目錄下的 `ManualDemo`。
- 第一次執行失敗，錯誤是 `Unresolved compilation problem`。查出原因是 VS Code 的 Java 語言伺服器仍以 Java 17 重新編譯，蓋掉 Maven 的輸出，不是程式邏輯錯誤。
- 改用 `mvn clean test` 後通過，並實際跑過 Mock 模式與 Email 失敗情境。
- 提供五種測試方式；其中 Gmail 實際寄送當時未驗證，也已說明。

### 4. 產出文件

**使用者：** 「好 所以依照需求都測試過了 對嗎 那幫我產出實作計畫跟測試報告」

**Claude：**
- 回答不完全對：Email 只寄到本機測試伺服器，未對真實郵件伺服器寄過。
- 跑變異驗證：節慶折扣改成 0.80 後有 4 個測試失敗，還原後 30 個全過。
- 建立線上文件，內含實作計畫與測試報告，並註明實作計畫是完成後整理。

### 5. 釐清「不完全對」

**使用者：** 問「捨麼東西不完全對」

**Claude：** 說明是在回答「都測試過了嗎」，指出兩件事：Email 沒有真的寄出、題目可能沒貼完整。

**Claude：** 確認模組三只有「發送通知」一項，沒有漏做，先前的推測是多慮，並更新報告。
